# Политика безопасности — Hranix

Hranix — privacy-продукт: доверие является его основным активом. Мы относимся к безопасности
самого приложения максимально серьёзно.

## Принципы (инварианты продукта)
- **Локально по умолчанию.** Панель (Hranix Shield) слушает только `localhost`. Доступ по сети —
  осознанный opt-in с TLS и авторизацией (JWT/RBAC).
- **Без телеметрии.** По умолчанию приложение НЕ отправляет никаких данных наружу. Любой сбор —
  только с явного согласия пользователя (диагностический бандл обезличен: персональные и
  финансовые данные не логируются, см. аналитический план §4.7).
- **Данные не покидают периметр.** Модель, база и индекс — локальные.

## Как сообщить об уязвимости
- **Не создавайте публичный GitHub Issue для уязвимостей.**
- Пишите приватно: **security@hranix.com (адрес указать при публикации)** или через GitHub Security
  Advisories (private).
- Мы подтверждаем получение в течение 72 часов и держим вас в курсе исправления.
- Приветствуется ответственное раскрытие; договорную дату публикации согласуем.

## Обычные баги и проблемы
Функциональные баги и предложения — обычные **GitHub Issues** (шаблон «баг/идея»). В приложении
есть кнопка «отправить отчёт» (обезличенный диагностический бандл, только с вашего согласия).

## Область
Политика распространяется на открытую часть Hranix (Hranix Shield, каркас модулей, Документы/
бэкапы, локальный RAG-движок — Фазы 0–2) под AGPLv3. Сторонние компоненты (CrowdSec, Wazuh,
Osquery, ClamAV) — по политикам их проектов.

> Черновик; контактный адрес, PGP-ключ и, при росте проекта, программа bug bounty — добавить
> перед первой публичной публикацией.
